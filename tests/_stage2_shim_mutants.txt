All three survivors were THE SAME DEFECT IN THREE PLACES, and it is the defect this stage was
written to stop, committed by the stage itself:

    M14  killing the allow-list gate     (`if ... in allow_list:` -> `if True:`)     GREEN
    M15  killing the stale-entry check   (`sorted(...)` -> `[]`)                     GREEN
    M16  asserting the module set against ITSELF (`expected, found` -> `expected,
         expected`)                                                                 GREEN

Each gate was written INLINE INSIDE ITS TEST, and after the retrofit the tree has no offender for
any of them to catch — every real translation site is allow-listed, no allow-list entry is stale,
and the declared module set matches. So each gate passed whether or not it worked. `test_the_
sweep_can_actually_fire` existed and was RED-able, but it graded the DETECTOR only; nothing stood
outside the GATES to check they would report anything.

That is doc 85's pin-that-grades-nothing shape exactly, and the stage-2 brief predicted it in as
many words: "three stages running have found a pin that was green while grading nothing." The
prediction landed on the stage's own guards.

THE FIX, applied to all three: extract each gate into a PURE FUNCTION that takes its inputs
(`undeclared_sites`, `stale_entries`, `module_set_drift`) and feed it synthetic offenders from a
test. A comparison written inline inside an assertion has nothing standing outside it to check
that it compares the right two things; a function does.

WHAT THIS COSTS TO BELIEVE: run 1 and run 2 are not "a lower score we improved on". They are the
evidence that a batch which only confirms what the builder already believed has not earned its
runtime — the same lesson stage 21 recorded, arrived at independently.
