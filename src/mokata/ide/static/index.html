                    How the graph works

                    A map of who calls what in this repo, built from your code — not from the agent's memory. A symbol is a named piece of your code — a function, a class or a method (like slugify). Each dot is one; each arrow is a call or an import, and clicking it shows the exact line that makes it true.

                    Read by: …

                    Start

                    1. Type a function or class name above the graph (e.g. slugify), or press Expand graph in the Impact tab beside a diff or a file.
                    2. Pick a view (below) and press Show.
                    3. Click a dot or arrow for its source. Double-click a dot to re-centre on it.

                    The views

                    What breaks
                    “If I change this, what else is affected?” The symbol sits in the middle; each ring further out is one more hop of callers. Tests sit on the outer ring.
                    Who calls
                    One step each way: who calls it (left) and what it calls (right).
                    Path
                    “How does A reach B?” The shortest chain of calls between two symbols.
                    Untested only
                    The caller chains into the symbol that no test runs — where a change could break something unnoticed.

                    Reading it

                    • solid arrow — the call graph proved this call or import.
                    • dashed arrow — only a name match (a hint, not proof).
                    • amber dot — on a chain no test reaches.
                    • ringed dot — a test.
                    • depth — how many hops out to look. Start at 2; raise it to see further, lower it if the picture gets crowded.

                    Nothing found? The symbol may be spelled differently, or the graph may not cover that language yet — the note under the details says which. No arrow is drawn that the graph cannot justify.
